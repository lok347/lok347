# 故障排查与历史验证记录

> 本文是 [零基础部署主教程](README.md)的附录。**遇到故障时按症状定位，不要在仍正常工作的 SG 节点上盲目重装或降级。**

## 最常见的四种问题

### 1. SSH 登录失败

- 在 EC2 控制台检查实例处于 `Running`，所选 Region 与实例一致。
- 检查所复制的 Public IPv4 是否仍是当前地址；重启实例后非固定公网 IPv4 可能改变。
- Security Group 入站 TCP 22 的 Source 是否包含你**当前**公网 IP；公司 Wi-Fi 与手机热点可能对应不同出口。
- Ubuntu 官方 AMI 默认 SSH 用户通常是 `ubuntu`，不要把登录用户直接换成 `root`。
- Mac 上执行 `chmod 400 "$EC2_KEY"`，检查文件路径与密钥正确。
- 第一次 SSH 指纹提示先核对连接的实例，再确认信任。

### 2. SSH 正常，但面板网页打不开

- 确认运行 SSH 本地转发命令的是 **Mac 新终端**，而不是 EC2 Shell。
- 隧道右侧端口必须是安装器打印的**面板随机端口**；不是代理端口 443。
- 浏览器使用 `http://127.0.0.1:18080/随机路径/`，不是 `http://EC2公网IP:面板端口`。
- 只要终端中的 `ssh -N -L ...` 关闭，该隧道即失效。
- 如 Mac 本地 18080 被占用，改成未使用的本地端口并同步修改浏览器地址。
- 用 `sudo x-ui` 菜单查看面板设置，确认面板进程正常、仅监听 EC2 localhost。**不要为了解决访问问题开放面板公网安全组端口。**

### 3. TCP 443 可达，但客户端连接失败

按下面顺序核对：

1. 面板入站是否启用，端口确为 443；EC2 安全组和本机防火墙有没有放行 TCP 443。
2. REALITY 中 **`Min Client Ver` 明确填写 `1.0.0`**；在我们此次实践中留空遇到过无法连通，修正后可用。**这属于当时版本的排障经验，非所有 Xray/REALITY 版本的通用要求。**
3. 客户端 Address 必须是 EC2 **公网 IP/域名**，不能是面板绑定地址 `127.0.0.1` 或 EC2 内网 IP。
4. Flow 是否是 `xtls-rprx-vision`，Transport 是 TCP/RAW，Security 是 REALITY，Fingerprint 是 `chrome`。
5. UUID、REALITY **公钥**、Short ID 和 serverName/SNI 是否与服务端逐项匹配。
6. 在服务器执行：

```bash
sudo x-ui status
sudo systemctl status x-ui --no-pager
sudo ss -lntp | grep ':443'
sudo journalctl -u x-ui -n 80 --no-pager
```

日志可能包含网络信息和配置字段，发到公开 issue 前先脱敏。

### 4. 客户端延迟测试通过，但实际访问网站失败

客户端测试通过不代表 HTTPS 访问一定成功。先在**服务器和客户端两端分别测试**，区分云主机出站问题与代理入站问题。再切换 Wi-Fi/蜂窝网络、重启客户端隧道、核对 REALITY SNI 与目标网站兼容性，最后才考虑 Xray 版本差异。

## 真实部署经验：Oregon 与 Singapore

| 项目 | Singapore / SG1 | Oregon |
| --- | --- | --- |
| 3x-ui 面板 | 历史安装目标 v3.8.5 | v3.8.5 |
| 入站 | VLESS + REALITY + XTLS Vision / TCP 443 | 同左 |
| Xray-core 历史可用版本 | **26.9.9** | **26.6.27** |
| 现象 | SG1 已通过网站与出口测试；公司热点下曾短时失效后恢复 | 26.9.9 曾客户端显示通、Google 却无法访问；回退到 26.6.27 后恢复 |
| 操作结论 | **不可因为 Oregon 的故障主动降级 SG1** | 先备份，再在 Xray 版本管理中切换至验证过的版本 |

**SG1 历史验收记录**：2026-09 的一次测试中，`https://www.google.com/generate_204` 连续 20/20 次返回成功，约 0.287–0.405 秒；20 MB 文件测试约 4.58 秒。这是当时特定时间与网络环境的结果，不能保证未来一直保持相同速度。

**Oregon 历史记录**：Xray 26.9.9 下曾出现客户端测试成功但 Google 不通；切回 26.6.27 后恢复连通，但加载部分图片仍偏慢。恢复连通不代表线路性能已经最佳；需要单独分析跨境链路、路由、拥塞、丢包、客户端 QUIC/UDP 等因素。

在旧节点内不建议用新安装器重装来处理版本问题。版本切换前通过面板备份，确认有恢复途径；随后使用面板中的 **Xray 版本管理**选择特定版本，逐项重新验证代理出口与实际网站。

## 日常维护与保密

- **已经可用的服务器不要重复执行“新装”流程。**
- 私密备份：面板导出、SQLite 数据库（常见 `/etc/x-ui/x-ui.db`）、REALITY 私钥、客户端 UUID/Short ID 和 SSH PEM 都只保存在安全的私有加密位置。
- GitHub 只发布占位符与脱敏图。不要公开 EC2 实例公网 IP、随机管理路径、密钥、完整客户端分享链接或二维码。
- 如果公网 IP 改变，先核对 EC2 当前 IP、客户端 Address 与 SSH 命令。
- AWS 实例、IPv4、流量及弹性公网 IP 可能产生费用；停用时应按 AWS 实际计费资源逐项清理。
- 早期使用过的 **S-UI + sing-box** 不是 3x-ui + Xray-core，不要混用配置、面板服务名或数据库。
